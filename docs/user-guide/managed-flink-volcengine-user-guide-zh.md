# StreamPark 火山引擎托管 Flink 用户手册

## 1. 手册说明

本文介绍如何通过 StreamPark 管理火山引擎流式计算 Flink 版，包括：

- 管理火山引擎云账号及 Team 授权；
- 创建和检测云托管 Flink 环境；
- 创建、编辑和发布 Flink SQL 应用；
- 启动、停止和重启应用；
- 创建快照（Savepoint）并从快照恢复；
- 查看 Provider 状态、运行指标和 Operation 审计信息；
- 定位常见权限、连接、发布和状态同步问题。

### 1.1 适用范围

| 项目 | 当前支持情况 |
| --- | --- |
| 云厂商 | 火山引擎（Volcengine） |
| 部署模式 | 云托管 Application |
| Flink SQL | 支持创建、发布和生命周期管理 |
| Flink JAR | 可见配置入口；Artifact 传输能力完成前禁止发布 |
| 启动方式 | 无状态启动、恢复最新状态、从指定快照恢复 |
| 快照 | 支持创建、查看和指定快照恢复 |
| 停止并同时创建快照 | 当前环境不支持；需要先创建快照，再停止应用 |

本文中的“Provider”指火山引擎托管 Flink 服务，“Operation”指 StreamPark 提交到云厂商后的异步操作记录。

## 2. 使用前准备

### 2.1 云侧资源

开始前，请确认火山引擎账号下已经具备：

1. 可用的流式计算 Flink 版项目；
2. 项目内可用的资源池；
3. 用于保存作业草稿的草稿目录；
4. 具有相应项目访问权限的 Access Key 和 Secret Key；
5. StreamPark 所在网络能够访问火山引擎 OpenAPI。

建议为 StreamPark 创建独立的云访问身份，并按最小权限原则授权。不要使用个人长期密钥作为生产环境公共凭证。

### 2.2 StreamPark 服务配置

以下配置由 StreamPark 管理员在服务端完成，普通用户不需要接触凭证主密钥：

- 启用 Managed Flink 总开关；
- 启用 Volcengine Provider；
- 配置凭证加密主密钥和当前密钥版本；
- 如需自动同步云侧状态，启用 Managed Flink Watcher；
- 配置用户及 Team 的功能权限。

关键服务端配置项如下：

```yaml
streampark:
  managed-flink:
    enabled: true
    providers:
      volcengine:
        enabled: true
    watcher:
      enabled: true
```

凭证主密钥应通过环境变量或安全的密钥管理系统注入：

```text
STREAMPARK_MANAGED_FLINK_CREDENTIAL_MASTER_KEYS
STREAMPARK_MANAGED_FLINK_CREDENTIAL_ACTIVE_KEY_VERSION
```

请勿把主密钥、Access Key 或 Secret Key 提交到代码仓库。

### 2.3 用户权限

管理员应根据职责分配权限。常用权限如下：

| 使用场景 | 所需权限 |
| --- | --- |
| 查看云账号 | `cloud-account:view` |
| 创建云账号 | `cloud-account:create` |
| 修改或轮换云账号凭证 | `cloud-account:update` |
| 删除云账号 | `cloud-account:delete` |
| 授权云账号给 Team | `cloud-account:grant` |
| 创建、编辑或删除托管环境 | `cluster:create`、`cluster:update`、`cluster:delete` |
| 查看和创建应用 | `app:view`、`app:create` |
| 查看应用详情 | `app:detail` |
| 编辑应用 | `app:update` |
| 发布或执行 Provider 对账 | `app:release` |
| 启动或重启应用 | `app:start` |
| 停止应用 | `app:cancel` |
| 创建快照 | `savepoint:trigger` |

云账号还需要授权给用户当前所在的 Team。具有菜单权限但未获得云账号 Team 授权时，用户仍无法使用该账号创建托管环境。

## 3. 推荐使用流程

建议按以下顺序完成首次配置：

```text
创建云账号
  → 测试连接
  → 授权 Team
  → 创建托管环境
  → 测试环境
  → 创建 Flink SQL 应用
  → 发布
  → 启动
  → 创建快照
  → 停止
  → 从快照恢复
```

## 4. 配置云账号

### 4.1 创建云账号

1. 进入 **设置 → 云账号**。
2. 单击 **创建云账号**。
3. 填写以下信息：

| 字段 | 填写说明 |
| --- | --- |
| 账号名称 | StreamPark 内用于识别该账号的名称，建议包含用途和环境 |
| 云厂商 | 选择 `Volcengine` |
| 地域 | 填写云资源所在地域，例如控制台中项目所属地域 |
| Access Key | 火山引擎访问密钥 ID |
| Secret Key | 与 Access Key 配对的访问密钥 |
| 描述 | 可填写负责人、用途和有效期 |

4. 保存云账号。

云厂商 Endpoint 由 StreamPark 统一管理，用户不需要填写。Secret Key 仅可写入，保存后不会从服务端返回明文。

### 4.2 测试连接

创建完成后，在账号列表中单击 **测试连接**。

- 显示 **已连通**：凭证、地域、网络和基础 OpenAPI 调用正常；
- 显示 **连接失败**：查看“最近错误”和“请求 ID”，按第 11 章排查；
- 显示 **未测试**：账号尚未完成连接验证，不建议用于创建环境。

连接成功只表示账号能够访问云服务。项目和资源池是否可用，还需要在创建托管环境时进一步验证。

### 4.3 授权 Team

1. 在目标云账号的操作区单击 **Team 授权**。
2. 选择允许使用该账号的 Team。
3. 保存授权。

只有被授权 Team 的成员才能在托管环境表单中看到并选择该云账号。

### 4.4 更新或轮换凭证

编辑云账号时：

- Access Key 和 Secret Key 均留空：保留现有凭证；
- 需要轮换凭证：两个字段必须同时填写；
- 只填写其中一个字段：保存会被拒绝；
- 更新后应重新执行 **测试连接**。

如果页面提示数据版本冲突，说明账号已被其他操作更新。请刷新列表，重新打开编辑窗口后再提交。

### 4.5 禁用和删除

- **禁用**后，该账号不能继续用于新的托管环境操作；
- 已被托管环境引用的账号不能删除；
- 删除前应先确认没有环境和应用依赖该账号。

生产环境优先使用“禁用”阻断新操作，确认依赖关系后再决定是否删除。

## 5. 创建托管 Flink 环境

托管环境负责把 StreamPark 中的逻辑环境映射到火山引擎项目、资源池和草稿目录。

### 5.1 新建环境

1. 进入 **Flink → 集群**。
2. 单击新增集群。
3. 部署模式选择 **云托管 Application**。
4. 依次填写或选择：

| 字段 | 填写说明 |
| --- | --- |
| 集群名称 | StreamPark 中的环境名称，建议包含地域和用途 |
| 云账号 | 当前 Team 已获得授权且处于启用状态的账号 |
| 地域 | 根据云账号自动确定 |
| 项目 | 从云厂商实时加载的项目 |
| 资源池 | 从所选项目实时加载的资源池 |
| 草稿目录 ID | 火山引擎侧用于承载 Draft 的目录 ID |

项目和资源池采用级联加载：更换云账号会清空项目和资源池，更换项目会清空资源池。

### 5.2 测试环境

填写完成后单击 **测试环境**。

环境测试会验证：

- 云账号是否可用；
- 项目和资源池是否存在且可访问；
- 草稿目录是否有效；
- Provider 能力和可选引擎版本是否可以读取；
- 当前环境是否具备后续应用操作所需能力。

看到 **托管 Flink 环境可用** 后再保存或使用该环境。若提示能力信息不可用，请重新测试环境，不要直接创建应用。

### 5.3 修改环境

修改云账号、项目、资源池或草稿目录后，应再次执行环境测试。环境已经被应用使用时，修改映射关系可能影响后续发布和生命周期操作，生产环境变更前应先停止相关操作并记录原配置。

## 6. 创建托管 Flink SQL 应用

### 6.1 新建应用

1. 进入 **Flink → 应用**。
2. 单击新增应用。
3. 部署模式选择 **云托管 Application**。
4. 选择已经测试通过的 **托管环境**。
5. 作业类型选择 **Flink SQL**。
6. 完成应用定义并保存。

主要字段如下：

| 配置分组 | 字段 | 说明 |
| --- | --- | --- |
| 基本信息 | 应用名称 | 不能包含空格；建议保持云侧唯一且便于识别 |
| 基本信息 | 引擎版本 | 只能选择环境能力中返回的版本 |
| 作业定义 | Flink SQL | 需要发布到 Provider 的 SQL 内容 |
| 资源配置 | 并行度 | 作业默认并行度 |
| 资源配置 | TaskManager Slot 数 | 每个 TaskManager 的 Slot 数 |
| 资源配置 | TaskManager CPU/内存 | 必须满足云环境给出的最小值和步进约束 |
| 资源配置 | JobManager CPU/内存 | 必须满足云环境给出的最小值和步进约束 |
| Checkpoint | 是否启用、间隔、超时 | 超时时间必须大于或等于执行间隔 |
| 状态 | State TTL、Checkpoint Backend | 按业务状态大小和恢复要求配置 |
| 重启策略 | 不重启、固定延迟、失败率 | 选择后填写对应的次数、延迟或时间窗口 |
| 发布配置 | 优先级、调度策略 | 取值受当前环境能力约束 |
| 自定义参数 | 运行时/发布参数 | 每行一个 `key=value` |
| 其他 | Program Args、描述 | 按作业需要填写 |

保存只会更新 StreamPark 中的“候选定义”，不会自动更新云侧已部署版本。

### 6.2 编辑应用

应用编辑保存后，如果候选定义与已部署定义不同，详情页会提示本地存在尚未发布的修改。此时正在运行的云侧作业不会自动改变，需要再次执行发布。

### 6.3 Flink JAR 当前限制

界面可能显示 Flink JAR 作业类型及 JAR、Main Class、依赖资源等字段，但当前版本尚未完成 Artifact 传输闭环，因此托管 Flink JAR 发布保持禁用。

需要验证完整生命周期时，请使用 Flink SQL 应用。

## 7. 发布应用

### 7.1 发布的含义

发布会将当前候选定义固化为不可变快照，并在火山引擎侧创建或更新 Draft，然后完成云侧发布。

1. 在应用列表中找到目标托管应用。
2. 选择 **发布**。
3. 核对候选定义 Hash、当前已部署定义 Hash 和发布提示。
4. 单击 **确认发布**。
5. 在发布 Operation 中等待最终结果。

提交发布之后再保存的修改不会进入本次发布，而会成为下一次发布的候选定义。

### 7.2 查看发布进度

Provider 写操作是异步的。请求显示“已受理”并不代表已经发布成功，应继续观察 Operation 状态：

| 状态 | 含义 | 建议操作 |
| --- | --- | --- |
| `ACCEPTED` | 请求已受理，等待执行 | 等待并刷新 |
| `RUNNING` | 云侧发布执行中 | 等待完成 |
| `SUCCEEDED` | 发布成功 | 可以启动应用 |
| `FAILED` | 发布失败 | 查看错误和 Provider Request ID |
| `UNKNOWN` | 写入结果未知 | 先执行 Provider 对账，不要盲目重试 |

同一个候选定义的重复发布请求会尽量复用已有 Operation，以避免在云侧重复创建资源。

### 7.3 Provider 对账

当 Operation 为 `UNKNOWN`，或网络中断导致无法确定云侧写入结果时，使用 **对账 Provider 状态**。对账完成前不要连续单击发布，因为上一次操作可能已经在云侧成功。

## 8. 启动、重启和停止

### 8.1 首次启动

首次启动还没有 Provider 实例，只能选择 **无状态启动**：

1. 确认最近一次发布已经成功；
2. 选择 **启动**；
3. 恢复模式选择 **无状态启动**；
4. 确认操作；
5. 等待生命周期 Operation 成功；
6. 刷新应用状态，确认作业进入运行状态。

### 8.2 再次启动或重启

已有运行历史后，可按环境能力选择：

- **无状态启动**：不加载历史状态；
- **恢复最新状态**：由 Provider 选择最新可用状态；
- **从指定快照恢复**：选择一个已经完成的 Provider 快照。

执行前应确认 SQL、引擎版本和状态数据兼容。涉及状态结构或算子 UID 变化时，从旧快照恢复可能失败。

### 8.3 停止应用

1. 在应用列表中选择 **停止**；
2. 核对应用和当前 Provider 实例；
3. 确认停止；
4. 等待生命周期 Operation 成功；
5. 刷新并确认应用已停止。

当前火山引擎环境不支持“停止前创建快照”的合并操作。需要保留状态时，请严格执行：

```text
手工创建快照 → 等待快照完成 → 停止应用
```

不要在快照仍处于创建中时停止作业。

### 8.4 生命周期 Operation

启动、重启、停止和创建快照都是异步操作：

| 状态 | 含义 |
| --- | --- |
| `ACCEPTED` | 已受理，等待执行 |
| `RUNNING` | 操作执行中 |
| `SUCCEEDED` | 操作成功 |
| `FAILED` | 操作失败 |
| `UNKNOWN` | 结果未知，需要先对账 |

操作按钮返回成功提示仅代表请求已受理，最终结果以 Operation 和同步后的 Provider 状态为准。

## 9. 快照与恢复

### 9.1 创建快照

1. 确认应用正在运行；
2. 选择 **创建快照**；
3. 可填写本次快照说明；
4. 确认创建；
5. 等待快照 Operation 成功；
6. 在应用详情的 **快照** 区域刷新列表；
7. 确认快照已经完成，记录 Provider 快照 ID。

只有已完成的快照才能用于恢复。

### 9.2 从指定快照恢复

1. 确认目标应用处于可启动状态；
2. 选择 **启动**或 **重启**；
3. 恢复模式选择 **从指定快照恢复**；
4. 从列表中选择一个已完成快照；
5. 核对 Provider 快照 ID；
6. 提交并等待 Operation 成功；
7. 确认新的 Provider 实例进入运行状态。

这里使用的是 **Provider 快照 ID**，不是 HDFS、S3、TOS 或本地文件路径。不要手工粘贴 Savepoint 文件路径。

### 9.3 推荐的恢复演练

首次上线前建议完成一次闭环演练：

1. 发布测试 SQL；
2. 无状态启动并确认运行；
3. 创建快照并等待完成；
4. 停止应用；
5. 从刚创建的指定快照启动；
6. 验证业务状态和数据连续性；
7. 停止测试作业。

## 10. 查看详情和运行状态

托管应用详情包含以下信息：

- Provider、项目、资源池和执行模式；
- Provider 应用 ID 和实例 ID；
- Provider 原始状态；
- 候选定义、已部署定义和 Provider 定义 Hash；
- 最后同步时间、下次同步时间和连续同步失败次数；
- Provider 实时指标；
- 快照列表；
- 发布及生命周期 Operation 审计记录；
- Provider Request ID、错误原因和操作时间。

### 10.1 同步状态

| 页面状态 | 含义 | 处理建议 |
| --- | --- | --- |
| 同步健康 | StreamPark 与 Provider 状态同步正常 | 无需处理 |
| 等待同步 | 新资源尚未完成首次同步 | 稍后刷新 |
| 状态可能过期 | 连续同步失败，展示的是最后一次已知状态 | 检查账号、网络和 Provider |
| 定义已漂移 | Provider 定义与 StreamPark 已部署定义不一致 | 暂停变更，核对云侧操作 |
| Provider 对象缺失 | StreamPark 有记录，但云侧资源不存在 | 核对是否被云控制台删除 |
| 同步状态不可用 | 当前无法判断同步健康度 | 查看错误和 Operation |

如果本地候选定义发生变化，页面会单独提示“尚未发布的修改”。这不等同于 Provider 定义漂移：

- 尚未发布的修改：用户在 StreamPark 保存了新配置，但尚未发布；
- 定义漂移：云侧实际定义与 StreamPark 记录的已部署定义不同。

## 11. 常见问题排查

### 11.1 云账号测试连接失败

按以下顺序检查：

1. Access Key 和 Secret Key 是否成对且仍然有效；
2. 地域是否与目标项目一致；
3. 云访问身份是否具备流式计算 Flink 版访问权限；
4. StreamPark 服务是否能够解析并访问火山引擎 OpenAPI；
5. 服务端 Provider 开关是否启用；
6. 根据页面中的请求 ID 到服务端日志检索对应错误。

不要把完整 AK/SK 粘贴到工单、聊天或日志中。

### 11.2 看不到云账号

检查：

- 当前是否已经选择 Team；
- 云账号是否已授权给当前 Team；
- 云账号是否处于启用状态；
- 用户是否具备相应菜单和查看权限。

### 11.3 项目或资源池列表为空

检查：

- 云账号是否已经测试连通；
- 所选地域是否正确；
- AK/SK 是否有目标项目权限；
- 项目是否存在可用资源池；
- 重新选择云账号以触发元数据刷新。

### 11.4 环境测试失败

重点核对项目、资源池和草稿目录 ID。草稿目录 ID 是云厂商资源标识，不是目录显示名称。

如果提示元数据或能力不可用，刷新页面后重新测试环境。测试成功前不要继续创建应用。

### 11.5 发布按钮不可用

可能原因：

- 当前用户缺少 `app:release`；
- 应用类型是当前尚不能发布的托管 Flink JAR；
- 环境能力未成功加载；
- 应用定义不完整；
- 已有 Operation 正在执行；
- 应用状态不允许发布。

### 11.6 发布或生命周期操作长时间不结束

1. 打开 Operation 详情；
2. 记录 Operation ID 和 Provider Request ID；
3. 刷新操作状态；
4. 查看 Provider 控制台中的对应资源；
5. 状态为 `UNKNOWN` 时先执行对账；
6. 确认云侧未执行后，才考虑重新提交。

### 11.7 无法选择指定快照

检查：

- 当前应用是否已有快照；
- 快照是否已经完成；
- 快照是否属于当前 Provider 应用；
- 页面是否已刷新；
- 当前环境是否声明支持快照恢复。

创建中、失败或属于其他应用的快照不能用于恢复。

### 11.8 状态显示可能过期

这表示 Watcher 暂时无法从 Provider 获取最新状态。此时：

- 不要只根据页面显示连续执行启动或停止；
- 先检查云账号连接和网络；
- 查看 Provider 控制台确认真实状态；
- 等待同步恢复，必要时执行对账。

### 11.9 凭证更新失败

如果提示并发更新或版本冲突，刷新页面后重新编辑。如果提示凭证加解密错误，请联系管理员检查主密钥配置和密钥版本，不要反复覆盖云账号。

## 12. 安全与操作规范

1. 使用专用云访问身份，不共享个人长期凭证；
2. 按 Team 授权云账号，避免跨团队复用生产凭证；
3. 定期轮换 AK/SK，轮换后立即测试连接；
4. Secret Key 保存后不可读取，不通过截图、日志或聊天传播；
5. 云侧控制台的手工修改可能造成定义漂移；
6. 写操作结果未知时先对账，不盲目重试；
7. 生产停止前先创建快照并验证完成状态；
8. 从快照恢复前确认新旧 SQL、状态结构和 Flink 版本兼容；
9. 通过 Operation ID、Provider Request ID 和时间记录保留审计线索；
10. 测试、预发和生产使用不同云账号或至少使用不同项目和资源池隔离。

- [ ] Provider 实时指标和同步状态可查看；
- [ ] 快照创建成功并出现在快照列表；
- [ ] 应用停止成功；

## 14. 当前版本限制

- 仅提供火山引擎 Provider；
- 托管 Flink JAR 尚未打通 Artifact 传输和发布闭环；
- 当前火山引擎能力不支持“停止并创建快照”单步操作；
- Provider 写操作均为异步，不能把“请求已受理”视为最终成功；
- 云侧控制台直接修改资源可能造成定义漂移；
- 删除 StreamPark 本地记录前，应由管理员确认云侧资源和依赖关系；
- 功能开关默认关闭，需要管理员显式启用并配置凭证主密钥。

## 15. 术语表

| 术语 | 说明 |
| --- | --- |
| 云账号 | StreamPark 中加密保存的 Provider 身份和地域配置 |
| 托管环境 | 云账号、项目、资源池和草稿目录的逻辑组合 |
| 候选定义 | 用户最新保存、等待下一次发布的应用配置 |
| 已部署定义 | 最近一次成功发布到 Provider 的应用配置 |
| Draft | 火山引擎侧的作业草稿 |
| Release | 将候选定义固化并发布到 Provider |
| Operation | 一次异步发布或生命周期操作及其审计记录 |
| Provider 快照 ID | 云厂商生成的快照标识，用于指定快照恢复 |
| Watcher | 周期性同步 Provider 状态、指标和定义的后台任务 |
| 定义漂移 | Provider 实际定义与 StreamPark 已部署定义不一致 |
